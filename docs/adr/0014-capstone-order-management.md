# ADR 0014 · 以订单管理后台实现模块化单体

2026-11-19，P6-01。选内部订单管理作为毕业项目的唯一业务案例。一套应用承担登录、角色配置和订单审批，一套MySQL数据库承载订单、状态历史和审计，Redis用于可重建的菜单缓存。

模块化单体允许状态变更和历史写入共享本地事务，也保留明确的业务模块边界。拆成服务会引入跨进程授权、消息交付及分布式故障恢复的成本。课程第38至39章已有这些机制的独立实验。订单项目用一个部署单元完成授权、事务、故障恢复和部署验收。

Maven Reactor按构件编译和测试，实体和Mapper停留在所属模块，避免依靠包命名维持边界。MyBatis-Plus沿用P3已验证的版本，简单表复用Mapper能力，订单读写使用显式条件表达授权范围和状态前置条件。JPA的对象生命周期与隐式刷新适合另一类教学目标，jOOQ会为本项目增加独立生成流程。

后端启动入口装配权限读取、业务用例与数据库适配，Vue管理端依据OpenAPI生成客户端。业务范围、模块依赖、数据模型和状态行为由[毕业项目契约](../../project/ARCHITECTURE.md)记录。领域名称见[项目术语](../../CONTEXT.md)。
