## 跨章重点

- JVM 与线程。规范区分加载、链接、初始化和运行时区域，HotSpot 的编译阈值、对象物理布局由实现和运行条件决定。JDK 21 的虚拟线程解决线程规模与阻塞等待问题。Node 事件循环的阶段与 Java 线程调度有各自适用范围。[JVMS 21](https://docs.oracle.com/javase/specs/jvms/se21/html/) · [JDK Thread 21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Thread.html) · [Node 事件循环](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick)
- 代理与事务。Spring 代理模式中的直接自调用绕过 advice。事务传播决定物理事务是否共享，隔离可见性仍由数据库和读语句类别决定。两端事务示例继续用真实 MySQL 验证提交与回滚。[Spring 6.2 代理](https://docs.spring.io/spring-framework/reference/6.2/core/aop/proxying.html) · [Spring 6.2 事务传播](https://docs.spring.io/spring-framework/reference/6.2/data-access/transaction/declarative/tx-propagation.html) · [MySQL 8.4 隔离](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)
- 安全。JWT 声明、签名和服务端会话状态分开校验。应用参考刷新轮换防重放的安全模型。对外协议范围仍以本项目契约为准，后台权限边界由实际 HTTP 和 SQL 测试取证。[RFC 9700 刷新保护](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14.2) · [Spring Security 6.5 Servlet](https://docs.spring.io/spring-security/reference/6.5/servlet/architecture.html)
- 消息。网络故障可能导致发布方重新提交已经成功发布的消息。发布确认、消费确认和数据库事务各在其边界内提供保证，应用按可重投条件验证幂等和死信。[RabbitMQ 4.2 确认](https://www.rabbitmq.com/docs/4.2/confirms) · [RabbitMQ 4.2 可靠性](https://www.rabbitmq.com/docs/4.2/reliability)
- 交付。OpenAPI 快照声明 3.1.0，Compose 根据依赖条件与 readiness 决定启动门禁。数据库逻辑快照和时序告警分别验证恢复内容与故障窗口。[OpenAPI 3.1.0](https://spec.openapis.org/oas/v3.1.0.html) · [Compose 启动顺序](https://docs.docker.com/compose/how-tos/startup-order/) · [MySQL 8.4 mysqldump](https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html)
