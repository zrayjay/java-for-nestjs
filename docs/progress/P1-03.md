## 实际运行证据

本机Windows build22621，Microsoft JDK21.0.13.0.2、Boot3.5.16、Nest11.2.9、Node22.20.0、TS5.9.3，仓库根运行：

```powershell
.\mvnw.cmd --batch-mode --no-transfer-progress -pl examples/spring-boot-examples -am verify
npx --yes pnpm@10.34.9 examples:build
npx --yes pnpm@10.34.9 examples:test
```

Maven实际额外使用已有临时缓存`-o`及`-Dmaven.repo.local=<TEMP>/java-for-nestjs-tools/m2/repository`，Spring模块6项测试通过（本章5项、原Greeting1项），依赖greeting-core的9项测试也通过，无失败/错误/跳过。TS构建成功，本章新增5项Node测试通过，连同既有章节共12项通过。

可检查结果：

- 双端真实容器装配后greet均为`Hello @ 09:00`，默认定义在各自容器内共享；Java不同容器的Greeter不同。
- Spring缺TimeSource刷新失败，Nest未export令牌编译失败；失败由断言捕获，不用空依赖替代。
- Java prototype查找结果不同，注入单例Holder后字段不自动替换，ObjectProvider显式get才获取新实例。prototype初始化执行，context.close后未自动关闭，调用者close后标记改变。
- Nest默认Holder保留其Transient依赖，两个独立resolve产生不同对象；RequestToken相同ContextId相同、新ID不同，普通get明确拒绝作用域Provider。
- Spring事件顺序为constructed/before-init/init/after-init/advice/use/use/destroy：外部execute有advice，target内部viaSelf只追加use；Proxy.isProxyClass断言真实JDK代理。
- Nest单例在compile后只有constructed，init后追加module-init/bootstrap，显式close追加module-destroy/before-shutdown/shutdown；RequestToken未收到应用销毁Hook。

该实验没有HTTP/数据库，不补写成本机Windows完整Web/MySQL/Redis兼容证据。Java25及跨平台结果等实际CI后补记。
