## 故障矩阵

| 故障 | 触发与根因 | 修复与回归 | 证据 |
|---|---|---|---|
| Spring Bean缺失 | Consumer需要未注册Port，启动失败因果链必须含NoSuchBeanDefinitionException | 给同一配置注册Port，启动成功且Consumer得到该实例 | ContainerFaultTest.missingDependencyFailsForTheSpecificUnregisteredPort |
| Spring构造器环 | First依赖Second、Second依赖First，因果链含BeanCurrentlyInCreationException | 改为两个客户端依赖共享Port，启动成功且注入相同Port，不用开放循环开关掩盖问题 | ContainerFaultTest.constructorCycleFailsInsteadOfCreatingPartiallyInitializedPeers |
| Nest Provider缺失 | factory inject missing-port，真实TestingModule.compile拒绝 | 登记同一令牌后编译成功并核对实例 | container-fault.test第1项 |
| Nest factory循环 | 两个factory Provider互相inject，真实容器拒绝 | 两个factory共同依赖shared-port，构建成功且令牌实例一致 | container-fault.test第2项；不推广为所有Nest forwardRef机制 |
| Spring事务自调用 | target内部调用注解方法，绕开代理，异常后数据仍存在 | 外部通过Actions代理调用同一runtimeRollback，数据为0 | 第27章TransactionTest.selfInvocationBypassesTheDesiredTransaction / runtimeExceptionRollsBack |
| checked异常回滚误判 | 默认规则下checked异常仍提交 | 声明rollbackFor后真实数据库无写入 | checkedExceptionCommitsByDefault / explicitCheckedRollbackRuleRollsBack |
| REQUIRED内部异常被catch | 同一事务被标rollback-only，外部提交仍失败 | 不把catch当恢复；正常事务路径和显式独立事务路径分别验证提交边界 | caughtRequiredFailureStillMakesOuterCommitFail / normalReturnCommits / independentInnerCommitSurvivesOuterRollback |
| Prisma误用root Client | transaction回调里使用root Client，写入逃逸 | 使用回调tx对象，异常时真实回滚 | Prisma wrong-client负例 / callbackRollback正例 |
| 池耗尽 | max2连接均借出，第三借用SQLTransientConnectionException | try-with-resources归还后active0，再借SELECT1成功 | DataAccessTest.exhaustedPoolTimesOutAndClosedLogicalConnectionsReturnToPool |
| 资源所有者关闭 | 关闭独立拥有池 | isClosed=true且不能再借，不误称“归还后池不可用” | closingAnOwnedPoolReleasesItsLifecycleAndRejectsFurtherBorrows |
| 已执行迁移被改 | 临时目录拷贝V1并改列长度，validate失败 | 原始不可变迁移仍validate成功，不repair掩盖 | modifyingAnAppliedMigrationFailsChecksumValidation |
