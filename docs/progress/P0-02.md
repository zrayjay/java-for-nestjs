## 本机Linux运行命令

在Windows仓库目录执行，下列命令使用Docker Desktop Linux容器与具名Maven缓存；数据库端口由Testcontainers分配。

```powershell
docker run --rm `
  --mount 'type=bind,source=D:\JERRY\java-for-nestjs,target=/workspace' `
  -v /var/run/docker.sock:/var/run/docker.sock `
  -v java-for-nestjs-m2:/root/.m2 `
  -e TESTCONTAINERS_HOST_OVERRIDE=host.docker.internal `
  -w /workspace maven:3.9.11-eclipse-temurin-21 `
  mvn --batch-mode --no-transfer-progress `
  -f examples/compatibility-probe/pom.xml clean verify
```

Java25将镜像标签改为`maven:3.9.11-eclipse-temurin-25`。两者均在本机Linux容器执行，不能算作原生Windows或远程CI结果。探针行为与通用命令见[探针说明](../../examples/compatibility-probe/README.md)。

## 发现与修复

初轮4项测试通过，但打包阶段依赖解析失败；修复网络解析后重新运行完整verify才计为通过。Boot默认Flyway11.7.2输出MySQL8.4支持范围警告，显式固定11.20.3后复测通过，警告消失。

本机PATH中无Java/Maven；发现IntelliJ附带JBR25可用于不修改全局配置的原生验证。便携JDK下载遇到慢速/超时，环境状态按实际结果记录。

实际下载并解压Microsoft JDK21，在临时目录使用Maven3.9.11，未修改系统PATH/JAVA_HOME。为减少网络变量，将已下载的Maven缓存复制到临时本地仓库，以离线模式执行：

```powershell
$env:JAVA_HOME = '<临时Microsoft JDK21目录>'
& '<临时Maven目录>\bin\mvn.cmd' -o --batch-mode --no-transfer-progress `
  '-Dmaven.repo.local=<临时缓存目录>\repository' `
  -f examples/compatibility-probe/pom.xml clean verify
```

运行到Spring上下文初始化失败：`TestRestTemplate`创建JDK HTTP Client时抛出`Unable to establish loopback connection`；底层`UnixDomainSockets.connect`返回`Invalid argument: connect`。脱离Spring的`HttpClient.newHttpClient()`最小程序同样失败，说明该问题可在本机JDK层复现，但尚未确定操作系统侧根因。

可保存以下代码为`LoopbackProbe.java`，用对应JDK执行`java LoopbackProbe.java`复现；没有Spring、Maven或数据库依赖：

```java
class LoopbackProbe {
    public static void main(String[] args) {
        try (var client = java.net.http.HttpClient.newHttpClient()) {
            System.out.println("HttpClient OK");
        }
    }
}
```

IPv4偏好、短/长临时目录和旧SelectorProvider尝试未解决，未将这些尝试固化为项目配置。JBR25复现同类问题；因此不声称Windows原生兼容通过，也不将Docker结果代替该项。暂用已验证的Linux容器方式开发，原生Windows修复与复测保留为待验收事项。

Boot4首轮CI成功启动但数据库表不存在，MyBatis查询与回滚测试失败；补充模块化`spring-boot-starter-flyway`后四组合复测全部通过。
