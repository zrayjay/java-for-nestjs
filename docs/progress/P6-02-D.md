# P6-02-D · 订单状态与事务

2026-11-19。交付[订单迁移](../../project/java-modules/module-business/src/main/resources/db/migration/V3__orders_and_history.sql)、[订单服务](../../project/java-modules/module-business/src/main/java/dev/javafornestjs/capstone/orders/OrdersService.java)及[HTTP入口](../../project/apps/admin-server/src/main/java/dev/javafornestjs/capstone/OrdersController.java)。创建、编辑、提交、批准和取消均记录有序处理历史。所有范围判断和写入条件使用绑定参数。允许动作由当前身份、范围和状态计算，写请求重新检查。

Windows、Temurin 21、真实MySQL 8.4.7测试覆盖直接HTTP的401、403和404，两部门的数据隔离，按状态分页、显式拒绝自审批、并发审批及冲突优先级。授权校验后执行带旧版本和状态的条件更新，订单与历史共享事务。两次并发批准最多一次成功。

故障夹具先尝试MySQL触发器，普通测试用户因二进制日志配置不能创建触发器。最终在独立测试库放置一次历史版本键冲突，实际触发写历史失败并返回500。订单保持草稿及版本1，历史集合不变。清理夹具后，以版本1重试成功，该订单有且仅有两条历史。暂无生产式审计或Redis，相关交付归P6-02-E。

8ed54ad的[后端CI](https://github.com/zrayjay/java-for-nestjs/actions/runs/44504155294)已通过Java 21/25。独立复核后补充三项验证，分别是安全的500错误体、同部门只读权限不扩大本人取消权限、复核员可取消待复核订单。修订后本机十项真实MySQL测试通过。
