# P6-02-A · 后端Reactor与启动骨架

2026-11-19。按[订单契约](../../project/ARCHITECTURE.md)装配独立的[后端Reactor](../../project/pom.xml)，包含启动应用、Core、Web、安全、系统与订单六个构件。公共构件和两个业务构件受Maven Enforcer的传递依赖规则约束，只有启动构件可以同时装配两个业务构件。Core另有独立规则拒绝Spring依赖，Maven Reactor拒绝构件循环。

Windows本机Temurin 21.0.13、Maven 3.9.11验证如下：

- 默认临时目录复现[G0](G0.md#windows最小复现与局部修复)的AF_UNIX连接错误。仅在测试进程设置`-Djdk.net.unixdomain.tmpdir`为本机可用的仓库路径后，`mvnw.cmd -f project/pom.xml clean verify`的七个Reactor项目全部通过。实际随机端口HTTP测试1项通过，0跳过。
- 独立运行Reactor产出的Spring Boot JAR，在随机环回端口由curl收到`200 {"status":"UP"}`。
- 临时复制Reactor POM并给`common-web`注入到`module-business`的依赖。测试构建因`BannedDependencies`失败，输出明确指出禁止的业务构件。正常Reactor通过。

规范与规格独立复核覆盖构件图、传递依赖、HTTP测试和Windows操作指引。aea235a的[后端CI](https://github.com/zrayjay/java-for-nestjs/actions/runs/44497812762)在Linux Java 21及25通过完整Reactor、依赖规则、真实HTTP测试及打包。P6-02-A进入`in_review`。认证、迁移和订单行为由后续任务交付。
