## Windows最小复现与局部修复

原始`HttpClient.newHttpClient()`在Microsoft21.0.13.0.2和JBR25.0.4.1均因`UnixDomainSockets.connect`抛出`Invalid argument: connect`。脱离Spring后同样失败。

本次先复现，再比较TCP与指定目录的AF_UNIX。TCP环回成功；默认C盘临时目录的AF_UNIX连接失败，同一程序在仓库所在D盘目录成功。进程参数`-Djdk.net.unixdomain.tmpdir=D:\JERRY\java-for-nestjs`随后使两种JDK的HttpClient初始化及真实HTTP200/响应体断言通过。

```powershell
# 在仓库根，java须指向待验证JDK。默认失败是本机原始症状。
java examples/compatibility-probe/tools/HttpClientProbe.java
# 在本机实测目录重跑；该路径不是通用盘符要求。
java '-Djdk.net.unixdomain.tmpdir=D:\JERRY\java-for-nestjs' examples/compatibility-probe/tools/HttpClientProbe.java
```

本机结果：默认目录退出1；指定目录Java21/25均输出`NATIVE_HTTP_OK`、HTTP200和匹配响应体断言成功，退出0。这是已证实的路径绕行，不是操作系统侧根因已修复，也不代表所有Windows环境或全套框架兼容。
