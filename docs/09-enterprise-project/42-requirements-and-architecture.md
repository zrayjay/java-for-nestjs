## 知识点

### 从业务动作推导数据边界 {#ch42-kp01}

#### 1. 一句话定义

将订单的状态、动作和归属写成可检验的规则，再为每个动作分配权限及数据范围。

#### 2. 为什么需要它

已有NestJS后台常在同一Controller加入录入和审批。只给Controller挂一个编辑权限时，录单员可能直接调用审批，也可能从路径参数切换到其他部门记录。

#### 3. 生活类比

纸质订单单据的签字栏对应提交和批准，部门归档柜对应部门数据范围。能打开档案柜只代表可查阅，能否签字还要看职责以及是否为这张单据的经办人。

#### 4. Node.js / TypeScript / NestJS 技术对照

Nest Guard和Spring Security都能先判断是否允许进入某个接口。订单所有权、状态和版本需要从数据库当前行判断，可以在两端用相同的测试向量描述。

#### 5. 两端代码对照

**TS / NestJS端** · [任务访问实现](../../examples/nestjs-security-reference/src/tasks.ts)将当前用户的范围转换成数据库约束。

**Java / Spring Boot端** · [任务数据访问守卫](../../examples/security-lab/src/main/java/dev/javafornestjs/security/PolicyTaskRepository.java)和[Mapper](../../examples/security-lab/src/main/java/dev/javafornestjs/security/mapper/SecuredTaskMapper.java)展示对应的查询和写入条件。按[NestJS实验](../../examples/nestjs-security-reference/README.md)和[Java实验](../../examples/security-lab/README.md)准备一次性MySQL，依次运行各自测试，跨部门查询预期404。毕业项目将在这一语义上增加提交、批准、取消及版本检查。

#### 6. 原理与流程图

```mermaid
flowchart LR
  R[认证请求] --> P[校验指定动作权限]
  P --> S[按该动作的数据范围限制订单]
  S --> V[判断状态与请求版本]
  V --> U[事务内更新订单并追加历史]
```

本人的范围匹配当前部门及本人ID，部门范围只匹配当前部门。创建时由当前身份决定两个归属字段。不同动作的权限分别计算，同一角色里的查询授权不会扩大写入范围。

#### 7. 类比边界与错误直觉

纸单可在多人之间传递，数据库更新会并发发生。审批和取消可能同时读到待复核状态，条件更新需要校验版本并仅允许一个竞争者生效。

#### 8. 企业应用场景与选型

订单复核展示职责分离和事务历史，覆盖人员管理后台的常见权限组合。付款或对外发货需要不同的失败、补偿和合规语义，项目首版聚焦内部审批。

#### 9. 常见错误与排查

有部门读取权限的录单员也能取消同事订单时，用同一个身份对同一订单分别执行读取及取消，确认是否在查询后复用了读取范围。修订后应能读到订单，取消则返回404。

#### 10. 实操练习与验收

基础题：给两部门各安排一个录单员，列三种归属下的查询结果。迁移题：把Nest的权限元数据和SQL范围分别放进Java的接口层及Mapper。思考题：为何部门复核员兼任录单员后仍不能批准自己的订单？对照[验收路径](../../project/ARCHITECTURE.md#验收路径)，每项检查写出固定身份、动作、预期状态码和数据副作用。

### 模块化单体与构件边界 {#ch42-kp02}

#### 1. 一句话定义

模块化单体用一个运行单元处理请求，业务与公共能力由明确的构件依赖和表归属约束。

#### 2. 为什么需要它

项目初期往往只有一个发布团队。提前拆分用户服务和订单服务会把一次本地操作变成多个进程间调用，还需要决定权限变更何时对订单生效。

#### 3. 生活类比

同一办公楼内有接单、员工管理和公共前台。大楼对应部署单元，部门对应模块，前台用已约定的窗口联系部门。部门档案由各部门保管。类比描述职责分工，无法替代编译期依赖验证。

#### 4. Node.js / TypeScript / NestJS 技术对照

Nest模块通过 `imports` 和 `exports` 控制注入可见性。Maven声明决定编译时哪些其他构件可用，Spring再按显式配置组装运行实例。两个机制处理不同阶段的问题。

#### 5. 两端代码对照

**TS / NestJS端** · [安全实验装配入口](../../examples/nestjs-security-reference/src/app.ts)集中连接认证、路由和数据访问。

**Java / Spring Boot端** · [课程根POM](../../pom.xml)展示Reactor声明，[Spring装配示例](../../examples/spring-boot-examples/README.md)可运行。毕业项目构件关系决定于[模块依赖与归属](../../project/ARCHITECTURE.md#模块依赖与归属)，将由P6-02-A创建并验证。

#### 6. 原理与流程图

Reactor按依赖拓扑构建构件。启动时由admin-server装配Web入口、身份服务、角色管理与订单用例。运行时订单用例接收当前身份，由订单Mapper限制SQL范围；系统模块通过认证读取接口提供当前授权。完整构件图见[模块归属](../../project/ARCHITECTURE.md#模块依赖与归属)。

#### 7. 类比边界与错误直觉

在同一进程中可以调用已注入对象，并不意味着模块可以访问彼此的Mapper。构件图无环仍不足以杜绝模块直接查询对方表，还要审查SQL和迁移表的归属。

#### 8. 企业应用场景与选型

用同一数据源保留订单更新及历史记录的本地事务。MyBatis-Plus简化常规Mapper，授权与并发条件使用可直接审查的SQL。独立部署变得必要时，再按数据所有权和变更频率评估拆分。

#### 9. 常见错误与排查

公共Web构件若为了序列化而引用订单实体，说明应用边界没有完成映射。检查依赖树，并在启动模块的HTTP入口把业务结果转换成响应DTO。

#### 10. 实操练习与验收

基础题：逐个标记订单Mapper、刷新会话和控制器所属构件。迁移题：将一个Nest共享模块按构件依赖、运行时DI两层改画。思考题：改成两个数据库时哪个事务承诺会失效？检查构件图可拓扑排序，且从任一公共模块出发都不能到达业务模块。

### 可执行的接口契约 {#ch42-kp03}

#### 1. 一句话定义

接口契约约定请求、响应、状态码和可观察的副作用，供服务、客户端和测试共同核对。

#### 2. 为什么需要它

第二次批准同一订单时，前端需要区分旧版本、非法状态与访问越界。模糊的错误文本会使客户端根据字符串猜测何时刷新页面、何时提示越权。

#### 3. 生活类比

办理柜台的业务清单对应请求字段，回执编号对应请求ID，退件原因对应稳定错误码。回执的格式和编码可约定，实际是否完成办理还要核对业务记录。

#### 4. Node.js / TypeScript / NestJS 技术对照

NestJS和Spring MVC都可生成OpenAPI说明。TypeScript类型只能约束生成客户端的调用，服务端还要验证输入、保护接口，并为不同结果发送正确状态码。

#### 5. 两端代码对照

**TS / NestJS端** · [托管任务HTTP参照](../../examples/nestjs-security-reference/README.md)包含合法和拒绝响应。

**Java / Spring Boot端** · [合同演练](../07-testing-jvm/35-integration-and-contracts.md)提供真实HTTP验证命令。本章的[HTTP契约](../../project/ARCHITECTURE.md#http-契约)定义毕业项目操作，后端生成OpenAPI后再接入实际客户端。

#### 6. 原理与流程图

先约定请求与错误语义。后端实现用例并由注解生成OpenAPI快照。CI核对快照并生成客户端。端到端测试调用真实接口，断言授权、状态码、响应字段和存储后的结果。

#### 7. 类比边界与错误直觉

OpenAPI描述HTTP请求、响应和安全约定。生成客户端可以核对类型，运行测试负责验证真实授权和数据库副作用。越权负例应绕过界面直接调用接口。

#### 8. 企业应用场景与选型

浏览器客户端用字符串承接数据库ID，避免Java长整型超出JavaScript精确整数范围。金额按分保存，状态变更携带版本，前端可在409后重新读取当前状态。

#### 9. 常见错误与排查

契约检查若只比对JSON字段，可能漏掉接口返回200而订单历史未写入。先在合同测试检查响应，再读订单详情和历史进行固定断言；反例检查未产生新历史。

#### 10. 实操练习与验收

基础题：写下创建、提交和批准的三组请求与响应。迁移题：为已有的Nest或Spring HTTP测试增加跨部门直接请求。思考题：为什么本契约先检查版本，再检查状态，并把权限检查放在两者之前？执行 `pnpm chapters:check` 检查章节与路径，再用[验收路径](../../project/ARCHITECTURE.md#验收路径)逐项核对行为可否转为测试。
